# MIDI 歌曲段落与续播

在“找谱”导入 MIDI 后，回到“播放”选中曲目，点击“歌曲段落…”。首次打开会分析已转换的音符序列，估计 A 段、B 段等不同材料，并将相似的段落标为重复。播放页的段落下拉框用于选择整曲或某一段；勾选“循环”后，再点预览、开始演奏或立即播放即可循环该范围。

段落窗口可以改名为“前奏”“主歌”“副歌”“桥段”等，也可以修改起止时间、新增或删除段落、重新识别。修改后点击“保存修改”；点击“试听本段”或“演奏本段”也会先保存有效的修改。“演奏本段”默认有 3 秒倒计时，可勾选跳过。窗口关闭后，段落播放继续；停止、F8 或 Esc 会停止播放。

时间使用原曲谱的毫秒位置，界面精确到 0.001 秒；调整速度不会改变段落范围。每段采用开始包含、结束不包含的规则，避免相邻两段重复播放同一组音符。手动范围必须包含音符、不能相互重叠，可以留出空隙。段内拖动进度会限制在该段；选择“全曲”后可以自由定位。

“开始演奏”默认从保存的位置继续，倒计时 3 秒；“立即播放”发送游戏按键时跳过倒计时。本机发声使用“预览”。停止与 Esc 保留刚播放的精确音符位置，继续时从下一组音符开始；拖到 0% 后从头播放。正常播放完毕后再次开始会回到全曲或所选段落的开头。

进度与段落按曲谱保存到本机 `config.json`，切换曲目与重启会恢复进度，启动选中上次曲目。修改不会写入原 JSON/MIDI。谱子内容变化后，旧进度和旧段落不会套用到新内容；需重新识别。播放状态带独立的运行编号，旧播放线程的进度和结束消息不会覆盖新曲目。

## 识别方法与限制

当前方案仅依赖 NumPy，不需要原曲录音、外部识别 API 或下载模型。对转换后的 15 音阶音符提取音高、音级、和弦与密度特征，构建自相似矩阵，以多个时间范围内的结构变化和长停顿寻找边界，再比较段落旋律轮廓与音高分布，给相似材料分配相同 A/B 标签。时间窗口仅用于分析特征，不按固定小节或固定拍数切段。矩阵最多 600 × 600，长曲的时间分辨率会降低；边界对齐到已有音符。

所有自动分段都是估计。只有重复出现、且音符密度明显较高的组才可能标为“高潮候选”；这不等于确认副歌。仅靠 MIDI，缺少歌词、歌声与原曲音色，而且转换到光遇音域会丢失一些音乐信息，因此无法可靠判断所有歌曲的主歌、副歌、前奏等语义名称。短谱或证据不足时保留为全曲，由用户手动调整。

算法是面向符号音符的独立实现，参考下列开源项目与论文方法，没有复制它们的源码，也不依赖它们的音频识别模型：

- [libfmp](https://github.com/meinardmueller/libfmp)（MIT）与 [FMP 第四章](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C4/C4.html)：自相似、结构变化和重复材料分析。
- [MSAF](https://github.com/urinieto/msaf)（MIT）：音乐结构分割及标签框架。
- Jonathan Foote, *Automatic Audio Segmentation Using a Measure of Audio Novelty*, ICME 2000：相似矩阵两侧的结构变化方法。

[All-In-One](https://github.com/mir-aidj/all-in-one) 可给原曲音频标注主歌、副歌与桥段，但输入要求不适合这里仅有 MIDI 的情况，当前版本没有接入。
